# 命运编织者 · Ananke

SillyTavern（酒馆）第三方扩展 —— **大世界剧情助手 / 命运织机**。

自动编织**任务链**、**伏笔**、**命运牌**与**地图**，在主 AI 生成前完成一轮"剧情调度"，
让世界真正会自己运转：任务会推进、会失败、会留下后果，伏笔会倒计时，敌人会按实力上限投放。

---

## 安装

### 方式一：从 GitHub 直接安装（推荐）

1. 打开酒馆 → **扩展**（Extensions）面板
2. 点 **Install extension**（安装扩展）
3. 粘贴本仓库地址：
   ```
   https://github.com/<你的用户名>/<仓库名>
   ```
4. 点安装 → 刷新页面（F5）
5. 在扩展列表里确认「命运编织者 · Ananke」已启用

> 安装后目录为 `data/<你的用户名>/extensions/<仓库名>/`。
> 更新：在同一面板点 **Update**，或重新安装一次即可。

### 方式二：手动复制

把本仓库所有文件复制到：

```
SillyTavern/data/<你的用户名>/extensions/命运编织者-Ananke/
```

然后刷新页面。

### 依赖

- **酒馆助手（Tavern Helper）** —— 必装。插件会 hook `window.TavernHelper.generate` 实现「前置拦截」：
  没拿到剧情 AI 的调度结果，就不放行主 AI 生成。
- 未安装 Tavern Helper 时，插件会退回监听 `GENERATION_AFTER_COMMANDS` 事件。

### 首次配置

进入 **扩展 → 命运编织者 → 提示词&API** 面板：

1. 填 API 地址 / Key / 模型（支持任意 OpenAI 兼容接口）
   - 例：火山引擎方舟 → `https://ark.cn-beijing.volces.com/api/v3`，模型填推理接入点 `ep-xxxxxxxx`
2. 确认 6 个任务的开关与频率（默认即可）
3. 发送任意一条消息开局 —— 首轮会自动生成「世界摘要 → 阶段规划 → 剧情引擎」

## 任务架构

开局的「世界摘要 + 阶段规划」是地基，之后每轮由「剧情引擎」调度。

| 任务 | 名称 | 职责 | 触发时机 |
|---|---|---|---|
| Task 1A | 世界摘要（经线） | 从设定中提取世界观全景：世界基础 / 全景 / 实力体系 / 核心矛盾 / 索引 | 开局一次、手动可重跑 |
| Task 1B | 阶段规划（纬线） | 依据实力体系划分 3-5 个成长阶段 + 世界事件时间线 | 开局一次、手动可重跑 |
| Task 2A | 剧情引擎 | **调度核心**：读完整任务链/地图/大纲/时钟/伏笔，输出增量状态 + 注入指引 + 调度信号 | 每轮 |
| Task 2B | 任务链生成 | 依据引擎给出的轻量引子，续写完整任务链（梗概 / 事件链 / 三结局） | 收到 `MISSION_GEN` 时 |
| Task 2C | 地图生成 | 依据场景信号铸造封闭地图（区域结构 / 敌对预部署 / 区域元素） | 收到 `MAP_GEN` 时 |
| Task 3 | 命运牌 | 掷骰者：按节拍与因果出牌，投放涟漪 / 浪潮 / 风暴级干涉 | 每 N 轮（默认 4） |

### 调度信号

Task 2A 在 `<store>` 的 JSON 里发出信号，插件据此唤醒 2B / 2C：

| 信号 | 唤醒 | 含义 |
|---|---|---|
| `MISSION_GEN` | Task 2B | 无活跃任务链且冷却结束 → 投放新引子，生成任务链 |
| `MAP_GEN` | Task 2C | 进入封闭场景且尚无地图 → 生成地图 |

## 核心机制

### 敌对实力上限（重要）

投放敌对时的**实力上限 = 主角当前所处实力等级段 + 2 个等级段**。

> 这是**实力体系的跨段**，不是数值等级 +2。
> 例：修仙体系 练气 → 筑基 → 金丹；主角在练气，则敌对上限定为**金丹**，
> 而不是"练气三层"这种同一大境界内的数值。
>
> 目的：即使主角装备/天赋超前，也必须存在能构成威胁的对手，避免"毫无难度"的碾压。
> 大纲阶段的「等级区间」只是基准难度，不构成硬上限。

### 任务链冷却

任务链达成结局时，插件会**同步**：

- 清空 `task_chain` 并写入完成记录
- 把「后续伏笔」加入伏笔队列
- 启动 **3 游戏日冷却**（由插件权威维护，随游戏日自动递减，不依赖 AI 自报）

冷却 > 0 时不会投放新引子，避免任务链连续触发。

### 数据格式

- **`<store>`** —— 所有任务的存储部分，内部是**合法 JSON 对象**（严格结构化，避免漏标）
- **注入标签** —— 保持 prose 标记（`<supplement>` / `<map_inject>` / `<fate_inject>`），
  交给主 AI 作为演出素材，可被酒馆正则美化

插件解析时**先按 JSON 解析，失败自动回退旧 prose 格式**，并容错处理 markdown 围栏、
尾逗号、字符串内裸换行。

```
│   └── task3-fate.js         # 3  命运牌
└── src/
    ├── settings.js           # 全局配置 + 任务默认值 + 版本迁移
    ├── store.js              # 聊天级状态（结构化 + 序列化辅助）
    ├── scheduler.js          # 前置拦截 + 调度 + 信号触发 + 冷却
    ├── parser.js             # store(JSON/prose 双模) + 注入标签解析
    ├── prompt-builder.js     # 占位符替换（含 {{clock}}/{{task_chain}} 等）
    ├── llm.js / api.js       # LLM 调用（走 ST 服务端代理，解决 CORS）
    ├── logger.js / utils.js / runtime.js
    └── ui/                   # 6 面板 + 模态框 + 悬浮球
```

## 常见问题

**Q：点发送后主 AI 迟迟不回复？**
A：这是正常的「前置拦截」——插件正在跑剧情引擎（按任务数量，通常几秒到几十秒）。
   可在日志面板看到每一步。

**Q：提示词改了不生效？**
A：插件按 `manifest.json` / `settings.js` 里的版本号做迁移。
   升级后若提示词没刷新，去「提示词&API」面板点**恢复默认提示词**。

**Q：任务链一直重复触发？**
A：检查面板五日志中 Task 2A 的发送内容，「任务链数据」块里应能看到 `冷却剩余：N游戏日`。
   若为 0 而当前不该投放，说明冷却状态异常。
